# Production secrets directory

Do not store these files in the repository. On the Docker host, create:

```sh
install -d -m 700 /etc/hau-soc/secrets
```

Each file must be owned by the deployment account (or UID `1001` for the signer key) with mode
`0600`. The checkout only contains this documentation.

| File                       | Contents                                                                         | Consumed by                |
| -------------------------- | -------------------------------------------------------------------------------- | -------------------------- |
| `database_url`             | `mysql://badging:<db-password>@db:3306/badging` (internal Compose hostname `db`) | web, worker, migrate, seed |
| `db_password`              | MariaDB application-user password                                                | db                         |
| `db_root_password`         | MariaDB root password                                                            | db                         |
| `signer_token`             | Long random bearer token shared by web and signer                                | web, signer                |
| `signing_key`              | Private signing key JSON: `{"privateKeyMultibase":"z..."}`                       | signer                     |
| `brevo_smtp_password`      | Brevo SMTP password/API key                                                      | web, worker                |
| `brevo_webhook_secret`     | Brevo webhook HMAC secret                                                        | web                        |
| `bootstrap_admin_password` | One-time initial Administrator password                                          | seed                       |

Generate independent random values, for example:

```sh
openssl rand -base64 48 > /etc/hau-soc/secrets/signer_token
openssl rand -base64 48 > /etc/hau-soc/secrets/db_password
openssl rand -base64 48 > /etc/hau-soc/secrets/db_root_password
openssl rand -base64 48 > /etc/hau-soc/secrets/brevo_webhook_secret
openssl rand -base64 48 > /etc/hau-soc/secrets/bootstrap_admin_password
chmod 600 /etc/hau-soc/secrets/*
```

The signing key must be generated by `scripts/generate-signing-key.ts` under the approved key
lifecycle, never by copying a developer key. The signer runs as UID `1001`; on a Linux Docker host
the key file must be readable by that UID without becoming world-readable:

```sh
chown 1001:1001 /etc/hau-soc/secrets/signing_key
chmod 600 /etc/hau-soc/secrets/signing_key
```

`database_url` must contain the same password as `db_password`. URL-encode special characters in the
password. Never use `localhost` for the database host inside Compose.

Secrets are mounted as files under `/run/secrets/` and bridged into the environment at container
start by `deploy/docker-entrypoint-secrets.sh`. Do not add them to `deploy/production.env`.

Rotate `signer_token` and `brevo_webhook_secret` immediately if disclosed. Rotate the SMTP password
through Brevo and restart the web/worker services.
