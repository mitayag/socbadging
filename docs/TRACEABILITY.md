# Requirement Traceability

This matrix preserves the Phase 7 notification and operations mappings and adds the Phase 8 signed-credential evidence. Exact commands and results are recorded in the Phase task reports and the [local readiness report](conformance/open-badges-3-local-readiness.md).

| Requirement                       | Implemented evidence                                                                                                                                                                                                                                            |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1 Email notification             | Individual, batch, replacement, and revocation transactions create durable outbox jobs only after credential commit. Provider-neutral SMTP worker, retry/audit UI, Mailpit drill, and MariaDB integration tests cover delivery and outages.                     |
| P1 Cryptographic signing          | Internal-only signer creates EdDSA Data Integrity proofs. Web readiness validates the configured key ID and cryptosuite and fails closed on signer outage or mismatch. Private key material is mounted read-only and never exposed by public routes or reports. |
| FR-002 RBAC                       | Server-side Administrator/Faculty policies protect issuance, revocation, signing settings, notification queries, and retry actions. Unit, integration, and desktop/mobile E2E tests cover owner, non-owner, and role denial.                                    |
| FR-010 Individual Issuance        | Sign-before-commit flow creates an immutable signed credential, status allocation, audit record, and notification row atomically. Signer failure creates no issuance.                                                                                           |
| FR-011 Batch Issuance             | Stored validation preview precedes commit; deterministic row ordering and an exclusive renewable claim preserve atomic commit and idempotency. Every newly issued row reuses the individual signing contract.                                                   |
| FR-012 Unique Credential          | Opaque public identifiers, immutable issuance IDs, historical signed JSON-LD snapshots, deterministic duplicate selection, and replacement linkage are covered by unit and MariaDB tests.                                                                       |
| FR-013 Verification               | Public verifier validates the persisted signing key, Data Integrity proof, credential schema, signed status list, expiration, and key trust. Active, revoked, expired, compromised, tampered, replacement, and legacy states are tested.                        |
| FR-015 Credential Export          | Public and authenticated routes return immutable `application/ld+json` bytes. New credentials are Open Badges 3.0-aligned and cryptographically signed; legacy unsigned records are never presented as verified.                                                |
| FR-016 Revocation                 | Authorized, audited, idempotent revocation atomically regenerates and signs the Bitstring Status List, preserves credential history, and queues one notification.                                                                                               |
| FR-020 Audit Log                  | Issuance, batch, revocation, replacement, signing-key lifecycle, and notification retry actions retain privacy-safe audit evidence.                                                                                                                             |
| FR-021 Search/Filter              | Phase 7 notification search/filter and deterministic bounded pagination remain covered by the full regression suite.                                                                                                                                            |
| FR-023 System Settings            | Administrator-only issuer settings and public signing-key metadata are exposed without secret material; Faculty denial is covered in E2E. Existing credential snapshots remain immutable after settings changes.                                                |
| Security and privacy NFRs         | Public projections omit email, student number, internal IDs, roster data, audit context, secrets, and bearer tokens. Generic not-found behavior, rate limiting, safe logs, signer isolation, and sensitive-report rejection are tested.                         |
| Responsive and accessibility NFRs | Desktop and 390x844 Playwright projects cover responsive public/authenticated views, two-line branding, keyboard focus, labels, touch targets, wrapping, and error-overlay/console cleanliness. Phase 7 acceptance also records 768x1024 and 1440x900 checks.   |
| Docker and operations NFRs        | Fourteen migrations apply to disposable MariaDB 11.8. Secure signer Compose smoke, mismatched-key failure, health, recovery, backup/restore, notification worker, and production activation runbooks are retained.                                              |
| Phase 8 completion criteria       | Signed individual and batch issuance, signed revocation status, public verification, key lifecycle, replacement, Docker signer, conformance evidence, regression gates, and desktop/mobile E2E are implemented locally.                                         |

## Remaining External Milestones

Local development uses loopback HTTP identifiers strictly for disposable testing. Before production activation, deploy stable public HTTPS issuer, key, credential, and status-list URLs; verify anonymous external retrieval; run the current official 1EdTech conformance suite; submit the required evidence; and receive written approval. Until then, the product must not be described as 1EdTech or Open Badges certified.
