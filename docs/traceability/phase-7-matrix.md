## Browser acceptance record

- Page identity: `HAU SOC Badging System`, `/login`, current source served by Next.js 16.3.0.
- Viewports: 390×844, 768×1024, and 1440×900.
- Results: HAU SOC and Badging System occupied separate lines; logo remained visible; form labels were exposed; focused input had accent border and 4px focus ring; controls use shared minimum-height/touch-target rules; document width never exceeded viewport width; browser console returned no warnings or errors. The central reduced-motion query disables smooth scrolling and minimizes motion. Retry live regions are covered by `retry-notification-form.test.tsx`.
- The automated Phase 7 E2E repeats brand checks on login and authenticated Administrator/Faculty shells for desktop and mobile projects.

## Volume baseline

The notification query selects only the table projection, orders deterministically by `createdAt` and `id`, and requests at most 20 rows. A hand-checked 41-row test model produces pages of 20, 20, and 1 row. This is the acceptance baseline; timing is intentionally observational rather than a brittle CI threshold.
